### 顺手修掉一个实现脆弱点（重要）

`apriori.ts` 的 `itemsetKey` 原实现 `items.join('|')`，**依赖「数组已排序」
这个隐式约定**（注释里写了但类型没约束）。而 `genRules` 用它作 supMap 的 key，
顺序不一致就查不到支撑度 → **规则被静默丢弃**（不报错，只是不生成）。

改为 `[...items].sort().join('|')` 并加回归测试。
**写测试时正是这个约定先绊住了我，说明它是真实存在的坑。**

## 追加：VPS 一键部署（提交 84097ad）

### server.cjs —— 生产级静态服务器（零依赖）
lan-server.cjs 只适合局域网，暴露公网前补齐：
- gzip（实测 JS 232KB → 74.7KB，降 68%）
- 缓存策略：带 hash 资源 `immutable` 永久缓存；index.html `no-cache`
- 安全响应头含 CSP（`script-src 'self'`，因平台不加载外部脚本）
- `/healthz` 健康检查、SIGTERM 优雅退出、启动时静态索引（不每次 stat）
- 实测：健康检查/安全头/gzip/缓存头/404行为/SIGTERM 退出全部验证通过

### deploy-vps.sh —— 八步流程
本地构建 → SSH 检查 → 装 Node（Nodesource v20）→ rsync 上传 →
systemd → ufw → 健康检查 → 清理历史版本

设计要点（改这个脚本时别破坏）：
- **版本化发布目录** `releases/<时间戳>/` + 软链接 current，回滚只改链接
- **ufw 只放行绝不 `ufw enable`**（擅开防火墙会导致 SSH 断连，是 VPS 上的危险操作）
- **不动 SSH 配置、不改已有 Nginx/Apache**
- 健康检查失败时打印最近 30 行日志

### 踩坑（写 bash 脚本的通用教训）
1. **heredoc 不加引号会在本地展开变量**：`<<SYSTEMD`（无引号）会让 `$SUDO`
   在本地展开，但 SUDO 是远端赋值的 → 值为空。改用 `as_root` 函数解决
2. `"$SUDO"` 空值时会执行空命令 → 必须用函数处理空前缀
3. systemd 配 `User=nobody` 有权限坑（站点文件在 /opt 下需额外 chmod）→
   改为 root 运行 + ProtectSystem=strict 锁死写操作
